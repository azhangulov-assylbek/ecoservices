# ecoservices.kz — инструкции для Claude Code

## О проекте
ecoservices.kz — платформа цифровых сервисов для экологов предприятий и консультантов в Казахстане,
проект ТОО «ЭКОМЕКЕН» (ecomeken.kz). Три направления:
1. Цифровые сервисы. В бета-версии: «Проверка объекта по НДТ» и «ESG-отчёт по стандарту P5» (PMI–GPM).
2. Оборудование для мониторинга выбросов, воды, пыли и шума (заявки на КП).
3. Кабинет данных мониторинга (в разработке).
Цель: работающий MVP с платящими клиентами, пригодный для продажи проекта.

Название проекта и домена — **ecoservices.kz** (с «s»). Не путать с ecoservice.kz — это другая компания.

## Стек
Django 5.2 LTS, PostgreSQL (SQLite для быстрого локального запуска), шаблоны Django (+ HTMX по мере необходимости),
WhiteNoise, Gunicorn, Docker Compose, Caddy (HTTPS). Хостинг: AWS Lightsail (Франкфурт), см. docs/deploy-aws-lightsail.md.
Планируется: Celery + Redis, python-docx, модуль ИИ (в т.ч. через Amazon Bedrock).

## Структура
- `config/` — настройки (всё окружение через переменные, см. `.env.example`), `urls.py`,
  реестр сервисов `service_registry.py`, системные проверки `checks.py`
- `core/` — главная страница, приём заявок на оборудование
- `catalog/` — сервисы, группы, темы ЦУР, оборудование, заявки, подписки «Сообщить о запуске»
- `ndt/` — справочники НДТ, технологические показатели, техники (ключевой актив данных),
  без пользовательских страниц
- `ndt_check/`, `esg_p5/` — сервисы-приложения (стартовые страницы, бета)
- Планируются: `accounts/`, `reports/`, `ai/` (роли, отчёты, общий ИИ-модуль)
- `templates/`, `static/css/main.css` (утверждённый дизайн, вариант 3), `static/js/main.js`
- `docs/` — дорожная карта, решения, архитектура, инструкция по развёртыванию

## Архитектура: модульный монолит
Каждый пользовательский сервис — отдельное Django-приложение (`ndt_check`, `esg_p5`, ...),
подключается через `settings.ENABLED_SERVICES` и монтируется в `/services/<slug>/`. Правила:
сервисы не импортируют друг друга; `core` и `catalog` не импортируют сервисы напрямую, только
через `config.service_registry`; сервисы могут читать `catalog.Service` и `ndt`. Подробности,
схема слоёв и роль будущих `accounts`/`reports`/`ai` — в `docs/architecture.md`.

## Команды
- Локально без Docker: `python manage.py migrate && python manage.py runserver`
- С Docker: `docker compose up --build`
- Тесты: `python manage.py test`
- Администратор: `python manage.py createsuperuser`, затем `/admin/`

## Правила
- Интерфейс и тексты — простым языком, от лица пользователя, на трёх языках: русский (основной,
  без префикса в URL), казахский (`/kk/…`) и английский (`/en/…`) — через Django i18n. Новый текст
  в шаблонах — через `{% translate %}`/`{% blocktranslate %}`, в Python — через `gettext_lazy`/`gettext`,
  в `static/js/main.js` — через `gettext()`/`interpolate()` (каталог `/jsi18n/`, смонтирован внутри
  `i18n_patterns`, иначе `LocaleMiddleware` всегда отдаёт его на русском). Переводы — в
  `locale/{kk,en}/LC_MESSAGES/{django,djangojs}.po`; каждую новую строку добавлять в оба `.po` и
  компилировать в `.mo` (`manage.py compilemessages`, если установлен GNU gettext; в этом окружении
  его нет — компилятор `.po → .mo` для такого случая описан в истории задачи, писать заново не нужно,
  доработать существующие `.mo`). Тексты каталога (`catalog.Service`, `ServiceGroup`, `Equipment`)
  переводятся отдельными полями `*_kk`/`*_en` в модели и читаются через `display_name`/`display_description`/
  `display_parameters` (откат на русский, если перевод не заполнен) — не через `.po`.
- Дизайн: использовать токены и классы из `static/css/main.css`. Не добавлять официальные иконки,
  логотип или цветовое колесо ЦУР ООН (для коммерческого использования нужно разрешение ООН);
  номера ЦУР — только текстом.
- Данные НДТ: значения технологических показателей вносятся только из официальных текстов справочников
  (adilet.zan.kz) с обязательным указанием таблицы/пункта (`EmissionLimit.section`) и отметкой `verified`.
  Никогда не генерировать и не «додумывать» нормативные значения.
- Сравнение показателей с НДТ — детерминированный код по базе. ИИ используется только для объяснений,
  подбора техник и ответов на вопросы, всегда со ссылкой на источник.
- В текстах не заявлять о «собственных нейросетях»: сервис использует внешние языковые модели
  плюс собственную базу данных и алгоритмы сравнения.
- Отчёты — «предварительная оценка», не заменяют государственную экологическую экспертизу.
- Модуль ИИ должен позволять сменить модель (Claude, Gemini и др.) одной настройкой.
- Секреты только в `.env`. Каждое новое поведение — с тестами. Небольшие коммиты с понятными сообщениями.

## Работа с git
После каждой выполненной задачи:
1. Запустить тесты: `python manage.py test`. Если тесты падают — сначала починить, потом коммитить.
2. Сделать коммит с сообщением на русском языке: короткая строка в повелительном наклонении
   («Добавь…», «Исправь…») или отглагольным существительным («Подключение базы из POSTGRES_*»),
   при необходимости — пояснение в теле сообщения. Коммиты небольшие, по одной задаче.
3. **Перед `git push` спросить разрешения у меня.** Без явного согласия не пушить,
   не создавать ветки на удалённом сервере и не открывать pull request.
